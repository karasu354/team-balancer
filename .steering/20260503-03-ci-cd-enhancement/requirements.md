# 要件定義: GitHub Actions の CI/CD 強化

## 背景・目的

現状の GitHub Actions は `format:test` と `test:unit` のみを Pull Request で実行している。
この状態では、型破壊・ビルド破壊・E2E 回帰を PR 時点で検知しづらい。

目的は、日常開発で必要な品質ゲートを CI に集約し、
`develop` / `main` への反映時に再現可能な成果物を自動生成すること。

---

## ユーザーストーリー

1. 開発者として、PR 時点でフォーマット・型・ユニット・Fast E2E・ビルドを自動検証したい。なぜなら、レビュー前に破壊的変更を早期検知したいから。
2. 開発者として、Redis 依存の Integration E2E は手動起動に分離したい。なぜなら、通常 CI の安定性と速度を維持したいから。
3. 開発者として、`develop` / `main` への push 時にビルド成果物を保存したい。なぜなら、配布・デバッグ・将来のデプロイ作業に再利用したいから。

---

## 受け入れ条件

### 正常系

| # | シナリオ | 期待動作 |
|---|---|---|
| C-1 | PR を作成する | CI が format / typecheck / unit / fast-e2e / build を実行する |
| C-2 | `develop` へ push する | CI が成功し、ビルド成果物がアーティファクトとして保存される |
| C-3 | 手動で Integration E2E を起動する | `REDIS_URL` を使って Integration E2E が実行される |

### 異常系

| # | シナリオ | 期待動作 |
|---|---|---|
| C-4 | `REDIS_URL` 未設定で Integration E2E を起動する | workflow が明示的に失敗して理由を表示する |
| C-5 | 同一ブランチへ連続 push する | 古い実行がキャンセルされ、最新実行のみ継続する |

---

## スコープ外

- 本番環境への自動デプロイ
- クラウド基盤（Vercel / AWS など）の新規構築
- カバレッジ閾値の導入
