# design

## アーキテクチャ概要

本作業は新しい「UI/UX改善提案プロンプト」を定義するドキュメント作業であり、
アプリ本体コードは変更しない。

運用フローは次の3段とする。

1. UI/UX改善プロンプトが、対象コードを走査して改善候補を抽出する
2. 出力を優先度・実装コスト・仕様影響有無で分類する
3. 仕様影響あり項目は `/requirements` で要件化し、実装は `/implement` に渡す

## 影響ディレクトリと責務分離

- `components/`
  - 主対象。入力導線、操作性、視認性、状態表示、レスポンシブ、アクセシビリティの改善候補を抽出
- `pages/`
  - 画面全体の情報設計、セクション順、主要CTA配置、導線の詰まりを点検
- `composable/`
  - UIに返すデータ取得/保存時のエラー表示方針、ローディング/再試行導線の不足を点検
- `pages/api/`
  - UIエラー表示に影響するレスポンス粒度・ステータス整合を確認（実装変更はしない）
- `utils/`
  - UI表示に関わる計算・整形ロジックの説明性不足や責務逸脱を点検（仕様変更はしない）

## データモデル・型定義の変更点

- 本作業でデータモデル変更は行わない
- `PlayersJson` / `PlayerJson` を含む既存型は参照のみとし、破壊的変更提案は要件化扱いとする

## API変更有無と docs/team-balancer.v1.yaml への影響

- 既定では API 変更なし
- UI/UX改善提案が API 契約変更を伴う場合のみ、別作業で
  `docs/team-balancer.v1.yaml` 更新を必須化する

## 既存の fromJson / playersInfo 互換性への影響

- 本作業による直接影響はない
- 改善提案が JSON 形式に影響する場合は、互換性維持策を必須記載にしたうえで要件化へ回す

## プロンプト出力設計

UI/UX改善プロンプトは、候補ごとに次の項目を出力する。

- 対象箇所（ファイル/コンポーネント/機能単位）
- 現状課題
- ユーザー影響
- 改善提案（実装イメージ）
- 優先度（High/Medium/Low）
- 見積もり（S/M/L）
- 仕様影響判定（即時対応可 / 要件化推奨）

チェック観点は次を最低限含める。

- 初見ユーザーの理解しやすさ（文言、ラベル、順序）
- 操作効率（入力回数、戻り操作、重複操作）
- フィードバック品質（成功/失敗/処理中の明確性）
- モバイル利用時の視認性とタップしやすさ
- アクセシビリティ（キーボード操作、コントラスト、意味のあるラベル）

## 実装方針（今回候補の反映）

### 即時対応可（UI実装改善 / UX改善）

- `pages/index.tsx`
  - 主要CTAの優先度を視覚階層で統一する
- `components/*`
  - エラー表示・再試行導線・フォームラベル系の表示ルールを共通化する
  - フォーカス可視化とキーボード操作を統一する
- `composable/api.ts` + `pages/api/*`
  - 通信中/成功/失敗状態のUI連携インターフェースを統一する
- `pages/*`
  - モバイルの操作完了性を優先し、主要操作への到達性を改善する

### 要件化推奨（仕様影響あり）

- `pages/api/*` のエラー契約を `error: string` 中心から `code`/`message` へ標準化する案は
  API契約変更を伴うため、別 `.steering` で要件化する

## 検証方針（要調査項目の確定手順）

1. 対象ファイルを走査し、候補ごとに具体的なファイル/行番号を確定する
2. 候補を「即時対応可」と「要件化推奨」に再判定する
3. `tasks.md` では即時対応可のみを実装タスク化し、要件化推奨は調査/起票タスクとして分離する
4. 不変条件（10人条件、評価重み、`fromJson`/`playersInfo` 互換）への影響を各タスクで明示確認する

## 仕様整合メモ（矛盾時の採用方針）

- 整合確認:
  - `docs/team-balancer-spec.md` の UI/UX 方針（導線改善、状態可視化）とは整合する
  - `docs/team-balancer.v1.yaml` は現状 `Error` スキーマ中心で、`code`/`message` 標準化案とは差分がある
- 採用方針:
  - API契約変更案は本スコープで実装しない
  - `/requirements` へ誘導し、承認後に `docs/team-balancer.v1.yaml` 更新を前提として進める
