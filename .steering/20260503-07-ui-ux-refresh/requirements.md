# requirements

## 背景・目的

現行 UI/UX は、約1年前に「まず動くこと」を優先して暫定的に実装した経緯があり、
機能要件を満たしている一方で、情報の見通し・操作導線・視覚的一貫性に改善余地が大きい。
また、いきなり実装へ入ると方向性がぶれやすいため、まず UI/UX 方針を議論・合意し、その後に段階的にコードへ反映する。

本作業の目的は次のとおり。

1. Team Balancer の UI/UX 方針（見た目・導線・操作感）を合意する
2. 合意した方針を実装可能な粒度へ落とし込み、段階的に反映する
3. 既存仕様（10人条件、評価ロジック、保存/復元フロー）を壊さず体験品質を向上する
4. 暫定実装由来の課題（情報設計・操作ステップ・視認性）を棚卸しし、優先順位を付けて解消する
5. Copilot による全面 UI 試作を先に作成し、人間レビューで採用/不採用を判断して部分反映する

## ユーザーストーリー

- プレイヤーとして、画面を開いたときに次にやる操作が直感的に分かる UI にしたい。なぜなら準備時間を短縮したいから。
- 運営者として、入力・編集・分割・保存/復元の流れを迷わず進めたい。なぜなら試合開始までの段取りを安定化したいから。
- 開発者として、先に UI/UX 方針を合意してから実装したい。なぜなら手戻りを減らして品質を上げたいから。
- 開発者として、Copilot に一度全面 UI 案を出してもらい、良い部分だけを安全に取り込みたい。なぜなら発想を広げつつ破壊的変更のリスクを抑えたいから。

## 受け入れ条件

### 正常系

1. UI/UX 改善の議論結果が `.steering/20260503-07-ui-ux-refresh/` に文書化される
   - 現状課題
   - 採用案 / 不採用案
   - 判断理由（トレードオフ）
2. 改善方針に基づき、影響画面（入力・一覧・分割結果・保存/復元）ごとの実装タスクが定義される
3. Copilot が生成した全面 UI 試作に対して、人間が評価結果（採用 / 不採用 / 保留）を記録する
4. 本番反映は「部分採用」を原則とし、1PR 1テーマで段階的に適用する
5. 実装後に以下が成功する
   - `npm run format`
   - `npm run format:test`
   - `npm run test`
   - `npm run test:e2e:fast`
6. 主要フロー（プレイヤー追加→10人分割→保存/復元）の操作性が向上していることを確認できる
   - 初見で次操作が分かる
   - 不要な往復操作が減っている
   - 状態変化（実行中/成功/失敗）が視覚的に把握できる
7. ドキュメント（`docs/team-balancer-spec.md`、必要時 `docs/copilot-workflow.md`）へ変更点が反映される
8. プレイヤー編集導線が短縮される
   - 既存カード導線（展開→Edit→Save）に加え、一覧全体を連続編集できる導線を提供する
   - 編集対象プレイヤーまでの遷移回数が減っている
9. 「保存 / 復元」は利用タイミング（アプリ開始時・終了前）に合わせ、画面上部で常時アクセスしやすい配置になる

### 異常系

1. UI変更が既存仕様（10人条件、評価重み、JSON互換性）と衝突する場合、仕様優先で見直し方針を記録する
2. 編集導線を短縮する変更で既存カード編集機能が劣化する場合、旧導線を残したうえで並行提供する
3. 改善案が複数あり結論が出ない場合、比較軸（学習コスト、実装コスト、一貫性）で暫定採用案を決定する
4. 変更範囲が大きすぎる場合、フェーズ分割して段階リリースする
5. アクセシビリティやレスポンシブで劣化が確認された場合、マージ前に修正タスクへ戻す
6. 全面 UI 試作の差分が過大な場合、試作コミットは比較用途に限定し本番反映コミットを分離する

7. 日英の表記が統一される
   - 日本語を基本とし、英語のほうが自然に伝わる専門語句（例: Bulk Edit、Save/Load、Tier、Role）はそのまま英語表記を維持する
   - 同一画面で日本語と英語が混在する箇所は方針に沿って統一する
8. 初心者向け「サンプルデータ投入」機能が追加される
   - ボタン1クリックでランダムな10人のプレイヤーデータを投入できる
   - 既存プレイヤーが存在する場合は上書きリスクを示す注意書きを表示し、意図しない消去を防ぐ
   - 機能の目的（操作に慣れるためのサンプルデータ）が画面上で説明される
9. Bulk Edit 画面の1プレイヤー行がコンパクトになる
   - 各プレイヤーの編集フォームを横並び・折りたたみ等で縦スペースを削減する
   - 保存（Save）ボタンは Bulk Edit 全体で1つにまとめ、「変更をまとめて確定する」体験を提供する
   - 各行の変更はリアルタイムに state に反映し、一括 Save 時にまとめて commit する

### 異常系（追加）

7. サンプルデータ投入時に既存プレイヤーデータが存在する場合、確認なしで上書きしない

## スコープ外

- チーム分割アルゴリズムの仕様変更
- API 契約の変更（`docs/team-balancer.v1.yaml` の破壊的変更）
- Redis 運用方式の再設計
