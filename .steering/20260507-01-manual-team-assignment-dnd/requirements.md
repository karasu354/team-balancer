# requirements

## 背景・目的

現行の team-balancer は「自動チーム分割」が中心であり、主催者が意図的に役割配置を調整したい場合の操作性が不足している。
特に、ロールごとの微調整や直感的な配置変更を行いたいケースでは、再分割の試行回数が増え、意思決定コストが高い。

本施策の目的は次のとおり。

1. ユーザーカードをドラッグ&ドロップでロール枠へ割り当てる UI を提供する
2. 自動分割とは独立した「手動分割モード」を提供し、主催者が最終配置を直接調整できるようにする
3. 既存の10人条件、評価ロジック、JSON 互換性を維持しつつ UX を改善する
4. 既存 API 契約への影響有無を実装前に明確化し、破壊的変更を回避する

## ユーザーストーリー

- 主催者として、プレイヤーカードをドラッグして任意のチーム/ロールへ配置したい。なぜなら自動分割結果を短時間で実運用向けに微調整したいから。
- 参加者として、自動分割と手動分割を切り替えて使いたい。なぜなら公平性重視と納得感重視を場面で使い分けたいから。
- 主催者として、手動配置時に重複割り当てや未配置を防ぎたい。なぜなら誤った構成で試合開始するリスクを下げたいから。
- プロダクトオーナーとして、既存保存形式（fromJson / playersInfo）と API 互換性を維持したい。なぜなら既存データ破損や回帰を避けたいから。
- ユーザーとして、プレイヤーを入力した直後に構成結果がすぐ見えるようにしたい。なぜなら入力内容を確認してから確定したいから。
- 主催者として、手動分割完了時に各チームのバランス数値（評価値、ロール構成など）を確認したい。なぜなら分割の妥当性を数字で判断したいから。

## 受け入れ条件

### 正常系

1. プレイヤーカードをマウス操作でドラッグし、Blue/Red の各ロール枠へドロップできる
2. 同一プレイヤーは同時に複数枠へ配置できない
3. 手動分割モードでは、ユーザーが全10枠を埋めた状態で手動配置を確定できる
4. 自動分割モードと手動分割モードを明示的に切り替えできる
5. 自動分割結果を初期値として手動分割へ引き継げる（編集開始点として利用可能）
6. 手動分割結果は既存の分割結果表示領域で確認できる
7. 既存の10人条件（参加プレイヤーが10人ちょうど）を満たさない場合は手動確定を実行できない
8. 主要テスト（unit / e2e）が追加・更新され、回帰がない

### 異常系

1. 参加者が10人未満/超過の場合、ドラッグ操作は可能でも「確定」は不可とし理由を表示する
2. ドロップ先が無効（ロール不一致枠・既に埋まっている枠）な場合、配置を反映せず UI で失敗を示す
3. 未配置プレイヤーが残っている状態で確定操作した場合、エラー表示を行い確定しない
4. 既存 API が手動配置情報を想定していない場合は、保存対象外とし UI 内 state として扱う
5. キーボード/タッチ環境で DnD が不安定な場合、代替操作（クリック選択→配置）を後続課題として明示する

## スコープ外

- リアルタイム共同編集（複数ユーザー同時操作）
- 新規バックエンド API の追加（本タスクで必要性が確定した場合は別チケット化）
- モバイル向け完全なジェスチャ最適化（今回は PC マウス操作を優先）
- 評価スコア式・重みの変更
- fromJson / playersInfo の互換性を壊すデータ構造変更

## 実装後のレビュー指摘 / 問題点リスト

以下の項目は実装完了後のユーザーレビューで指摘されたもので、次フェーズにて対応を検討する。

1. **入力プレビューの配置改善**

   - 現状: 入力フォーム送信後に結果プレビューが表示される
   - 指摘: プレイヤー追加ボタン直前に配置し、入力直後に結果が見えるようにしたい
   - 影響: `components/PlayerInputForm.tsx` または `pages/index.tsx` のレイアウト調整

2. **プレイヤー一覧カード表示の再検討**

   - 現状: プレイヤーカード型で表示
   - 指摘: 描画領域を多く取っている割に情報が少ないため、別の表示形式（行型、コンパクト形式など）の検討を希望
   - 影響: `components/PlayersTable.tsx` のレイアウト・スタイル見直し

3. **手動分割モードのチームバランス数値表示**

   - 現状: 手動分割完了後、チーム構成の確認はできるが数値情報は表示されていない
   - 指摘: 自動分割と同様にチームバランス（評価値、ロール構成数など）を数値で表示したい
   - 影響: `components/DividedTeamTable.tsx` の手動モード表示領域に数値情報を追加

4. **試合履歴セクションのダークテーマ適用**
   - 現状: 試合履歴パネルのテーマが他セクションと不統一の可能性
   - 指摘: 他のデザインと同様にダークテーマを適用してほしい
   - 影響: `components/MatchHistoryPanel.tsx`, `components/MatchHistoryAccordion.tsx` のスタイル修正

## 既存仕様との整合・採用方針

- 10人条件: 維持（自動/手動とも確定は10人時のみ）
- API 互換性: 現時点は「不明」のため、初期方針は API 非変更・フロント状態管理で実装し、必要時のみ `requirements-update` で追記する
- 既存 UI フロー: 自動分割を主導線として維持し、手動分割は補助導線として追加する
