# requirements

## 背景・目的

現行アプリは機能要件を満たしている一方、視覚的なブランド性と情報密度の最適化に改善余地がある。
League of Legends 利用者にとって直感的な体験を提供するため、OP.GG 風の情報設計・配色・表示強調を導入し、入力から分割結果確認までの体験を改善する。

本作業の目的は次のとおり。

1. OP.GG 風の UI トーン（ダーク基調 + ブルーアクセント）を導入し、第一印象を改善する
2. プレイヤー入力と分割結果の視認性を高め、判断コストを下げる
3. 既存仕様（10人条件、JSON互換性）を維持したまま UI/UX を改善する
4. いただいた UI/UX 改善候補（High/Medium）を実装可能な粒度に分解する
5. 入力視認性・分割画面導線の追加要望を反映し、操作の迷いを減らす
6. 一括編集時の白背景優勢を抑え、ダークテーマ基調へ統一して目の負担を下げる
7. 分割結果表示と試合結果確定フローの安心感を高め、誤操作や違和感を減らす

## ユーザーストーリー

- 参加者として、プレイヤー入力時にランクと強さをカードで直感的に把握したい。なぜなら入力ミスや抜け漏れを減らしたいから。
- 主催者として、10人揃うまでの進捗をひと目で確認したい。なぜなら分割実行可能タイミングを即座に判断したいから。
- 参加者として、分割結果のチームバランスを視覚的に比較したい。なぜなら結果の納得感を短時間で得たいから。
- プロダクトオーナーとして、既存ドメイン仕様を壊さずに見た目と操作性だけを段階的に改善したい。なぜなら回帰リスクを抑えたいから。
- 参加者として、背景が白い入力欄では黒文字で入力したい。なぜなら入力値を見失わずに編集したいから。
- 主催者として、プレイヤー追加セクションを必要なときだけ開きたい。なぜなら画面の情報密度を下げたいから。
- 参加者として、チーム分割画面で「分割結果」と「履歴」をタブ切り替えしたい。なぜなら確認したい情報へ最短で移動したいから。
- 参加者として、プレイヤーカード上のすべての文字をダークな背景でも読みたい。なぜなら文字が見えないと情報確認ができないから。
- 主催者として、分割実行可否は分割操作エリアで明確に把握したい。なぜなら入力フォーム側には追加に必要な情報だけを残したいから。
- 参加者として、プレイヤー入力欄のラベル（名前・ティアなど）をダーク背景でも読みたい。なぜなら各フィールドが何の入力欄か判断できないと入力ミスに繋がるから。
- 参加者として、UI 全体の文字を背景色に関わらず読みたい。なぜなら操作手順や情報がどこにあっても把握できることが大前提だから。
- 参加者として、一括編集へ遷移したときも白の面積が強すぎない画面で操作したい。なぜなら長時間の編集で視認疲労を減らしたいから。
- 参加者として、入力プレビューはプレイヤー追加フォームより上で先に確認したい。なぜなら追加操作の前に入力内容の妥当性を判断したいから。
- 主催者として、プレイヤー追加フォーム内に人数表示（x/10）や達成メッセージは出さないでほしい。なぜなら情報を絞って入力操作に集中したいから。
- 主催者として、サンプルデータ投入ボタンはプレイヤーが1人以上いる場合は表示しないでほしい。なぜなら誤投入を避けたいから。
- 参加者として、サブタイトルの「OPGG風〜」文言は表示しないでほしい。なぜなら冗長な説明より主要操作を優先して見たいから。
- 参加者として、「Copy to Clipboard」のような英語文言ではなく日本語表記で操作したい。なぜなら画面全体の言語統一で迷いを減らしたいから。
- 参加者として、「分割結果」と「履歴」のタブ切替時に画面下部でズレを感じない表示にしたい。なぜなら切り替え時の違和感を減らしたいから。
- 参加者として、チーム分け実行中は前の結果が隠れるなど、新しい分割処理中だと分かる表示にしてほしい。なぜなら処理状態の取り違えを防ぎたいから。
- 主催者として、総レート差が目立ちすぎないよう評価スコアの重みを調整したい。なぜなら体感に合う分割結果へ近づけたいから。
- 主催者として、試合結果の確定後に最終確認を行い、さらに確定後は選択状態（青チーム勝利など）をリセットしてほしい。なぜなら誤確定と連続誤操作を防ぎたいから。

## 受け入れ条件

### 正常系

1. ページ全体が OP.GG 風のダークテーマで統一され、ブランドカラーをブルー系で一貫適用する
2. プレイヤー入力 UI がカード型で表示され、ランクが色付きバッジまたはアイコンで識別できる
3. 入力中にスコアまたはレートのプレビューを確認できる
4. 入力プレビューがプレイヤー追加フォームより上に配置され、追加前に内容確認できる
5. 分割準備率（%）は表示しない
6. 分割結果で Blue/Red の比較が横並びで確認でき、評価スコア差が強調表示される
7. 各プレイヤーの貢献度を補助的な可視化（バーなど）で確認できる
8. ヘッダーにロゴ/サービス名を配置し、保存済みチーム導線へアクセスできる
9. 主要フォームでキーボード操作（Enter による次入力または実行）が改善される
10. 背景が白い入力要素は黒文字で表示し、入力値の視認性を担保する
11. プレイヤー追加セクションはアコーディオンで開閉できる
12. チーム分割領域は「分割結果」と「履歴」をタブで切り替えできる
13. モバイル表示で主要操作（入力・追加・分割・確認）が崩れず完了できる
14. 変更後に主要テストが成功する
15. プレイヤーカードの文字色がダークテーマの背景に対して十分なコントラストを持ち、すべての情報を読めること
16. プレイヤー追加フォーム内では参加人数（x/10）表示を行わず、進捗バーも表示しないこと
17. Input 系コンポーネント（InputText / Dropdown / CheckBox / Textarea）のラベル文字色がダーク背景で視認できること
18. 全コンポーネントで light 系固定カラー（text-gray-_, text-slate-_ 等）をテーマ変数またはダーク対応クラスへ置換し、UI 全体の文字視認性を確保すること
19. 一括編集領域を含む主要 UI がダークテーマ基調で統一され、白背景の過剰使用を避けること
20. プレイヤーが1人以上存在する場合、サンプルデータ投入ボタンは非表示になること
21. サブタイトルの「OPGG風〜」文言は画面上に表示されないこと
22. 「10人揃いました。チーム分けを実行できます」メッセージは表示しないこと
23. チーム分割のコピー操作文言は「クリップボードにコピー」等の日本語表記で統一すること
24. 「分割結果」と「履歴」のタブ切替時に、下端スクロール位置でレイアウトジャンプや高さ差による視覚的なズレが発生しないこと
25. 「チーム分け」実行中は旧結果をそのまま見せ続けず、ローディング状態やプレースホルダで新規計算中だと判別できること
26. 評価スコアの重みは総レート差の寄与が過度に強くならないよう再調整し、重み変更後もロジック整合とテストが維持されること
27. 試合結果確定では確定直前に再確認ステップを設け、確定後は勝敗選択状態（青チーム勝利/赤チーム勝利）をクリアすること

- npm run format
- npm run format:test
- npm run typecheck
- npm run test
- npm run test:e2e

### 異常系

1. 参加人数が10人以外のとき、分割処理は実行されず、理由が画面で明示される
2. ダークテーマ適用後にコントラスト不足が発生した場合、WCAG を意識した配色へ再調整する
3. キーボード操作改善が既存入力フローを壊す場合、機能フラグまたは段階導入で回避する
4. UI 改修により E2E が不安定化した場合、セレクタを role/label 優先へ見直して回帰を防ぐ
5. 入力欄が白背景のまま文字色も白になった場合、黒文字へ強制して可読性を回復する
6. アコーディオン初期状態で入力不可にならないよう、開閉状態とフォーカス制御を検証する
7. 人数表示と達成メッセージを削除したことで分割実行条件の理解が下がる場合、ボタン disabled 状態と補助文言で条件を補完する
8. タブ切替時に表示高さが変動する場合、固定高/最小高またはコンテナ揃えでジャンプを抑制する
9. 重み調整によって極端な偏りや既存バランスが崩れる場合、比較データとテストで回帰検証する
10. 試合結果の再確認導入で操作手数が過剰になる場合、確認UIの文言と操作回数を最小化して離脱を防ぐ

## 問題点リスト（追加）

- 入力コントロールの背景色と文字色の組み合わせに一貫性がなく、環境によって可読性が落ちる可能性がある
- 分割準備率（%）と参加人数（x/10）が重複情報となり、視線誘導を阻害する
- チーム分割画面で履歴が常時表示されるため、結果比較時の情報密度が高い
- PlayerCard が旧ライトテーマ配色（bg-gray-200, text-gray-600 等）を残したままのため、ダーク背景でテキストがほぼ見えない
- PlayerInputForm の参加人数を示す進捗バーがあるが、バー自体は不要でシンプルなカウント表示（x/10人）で十分
- Input 系コンポーネントのラベルに text-slate-700 を使用しており、ダーク背景で視認不能になる
- プロジェクト全体に light 系固定カラーが散在しており、ダークテーマ化が部分的に留まっている
- 一括編集画面で白背景領域が強く、ダークテーマとしての統一感と視認負荷低減が不足している
- 入力プレビュー位置がプレイヤー追加フォームより下にあり、追加前確認の導線が弱い
- プレイヤー追加フォームに人数表示（x/10）と達成メッセージが残っており、情報の簡素化方針に反する
- サンプルデータ投入ボタンが既存プレイヤーありでも表示され、誤操作リスクがある
- サブタイトル「OPGG風〜」が残っており、主操作より説明文が先に目立つ
- チーム分割のコピー操作文言が英語で、画面内の日本語UIとトーンが不一致になっている
- 「分割結果」と「履歴」のタブ切替時にコンテナ高さが揃わず、最下部付近で視覚的なズレが出る
- 「チーム分け」実行中に前回結果が見え続けるため、再計算中かどうか判別しづらい
- 評価スコアで総レート差の体感寄与が高く、重み見直し要望に対して現状値が固定化されている
- 試合結果確定時に最終確認がなく、確定後も勝敗選択が残るため誤操作の連鎖リスクがある

## スコープ外

- チーム分割ロジックの構造変更（評価式の重み再調整は本施策の対象）
- 参加人数10人条件の変更
- fromJson / playersInfo の互換性変更
- API 契約変更（本施策では docs/team-balancer.v1.yaml の変更は行わない）
- 新規バックエンド機能追加
