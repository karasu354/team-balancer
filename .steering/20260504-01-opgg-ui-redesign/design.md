# design

## アーキテクチャ概要

本施策は UI/UX 改善を目的とし、ドメインロジックと API 契約を維持したまま表示層を再設計する。
追加要望（入力文字色、分割準備率削除、入力アコーディオン化、分割/履歴タブ化、白背景抑制、表示要素整理、日本語文言統一、分割中状態可視化、重み調整、結果確定再確認）を反映し、
視認性と導線のシンプル化を優先する。

実装は次の4層で進める。

1. テーマと入力視認性

- 白背景入力要素の文字色を黒へ統一する
- テーマ変数の適用優先順位を定義し、可読性を最優先にする
- light 系固定カラークラス（text-gray-_, text-slate-_, bg-gray-\* 等）を CSS テーマ変数（--tb-text-primary / --tb-surface 等）または dark 対応クラスへ全面的に置換する
- PlayerCard の文字色・背景色をダークテーマ変数へ統一する
- Input 系コンポーネントのラベル文字色を `text-[var(--tb-text-primary)]` または `text-[var(--tb-text-secondary)]` へ統一する
- 一括編集領域を含む主要コンポーネントで白背景を抑え、ダークテーマ変数ベースの配色へ統一する

2. 入力導線

- プレイヤー追加領域をアコーディオン化し、初期表示と開閉状態を明確にする
- 入力プレビューはプレイヤー追加フォームより上へ配置し、追加前確認導線を優先する
- プレイヤー追加フォームから人数表示（x/10）と達成メッセージを除去し、入力操作に集中できる情報量へ整理する

3. 分割導線

- 分割画面を「分割結果」「履歴」タブへ分離し、目的別に情報表示を切り替える
- 分割準備率（%）は廃止し、分割条件の案内は分割操作エリア側へ集約する
- PlayerInputForm では人数カウント（x/10）と進捗バーを表示しない
- 分割結果/履歴タブは表示領域の高さ揃え（固定高/最小高）を行い、切替時のレイアウトジャンプを抑制する
- 「チーム分け」実行中は旧結果を一時的に隠し、ローディング状態を明確化する
- Copy 操作文言は日本語へ統一する

4. 評価ロジックと結果確定導線

- 評価スコアの重みを再調整し、総レート差の寄与が過剰にならないよう再配分する
- 試合結果確定は二段階確認（確定前確認）を追加し、確定後は勝敗選択状態をクリアする

5. 回帰防止

- E2E を role/label 中心で維持し、タブ切替変更によるセレクタ破綻を防ぐ

## 影響ディレクトリと責務分離

- utils/

  - teamBalancer.ts の評価重み定数を調整対象とする（分割条件と JSON 互換性は不変）

- components/

  - PlayerInputForm 系: 入力アコーディオン開閉、入力文字色の担保、進捗バーと人数表示と達成メッセージの廃止
  - SinglePlayerInputForm 系: 入力プレビューの表示位置をプレイヤー追加フォームより上へ再配置
  - PlayersTable 系: 一括編集時の背景・文字配色をダークテーマへ寄せる
  - DividedTeamTable 系: 分割結果/履歴タブ切替、分割準備率削除、コピー文言日本語化、分割中ローディング状態可視化、タブ切替時の高さ揃え
  - MatchHistory/結果確定 UI 系: 確定前の再確認導線追加、確定後の選択状態クリア
  - Input 系: 白背景入力の文字色を黒で統一、ラベル文字色を CSS テーマ変数へ統一
  - PlayerCard 系: 旧 light テーマ固定色（bg-gray-200, text-gray-600 等）を CSS テーマ変数へ置換
  - サンプルデータ投入 UI: プレイヤーが1人以上いる場合は非表示へ変更

- composable/

  - API 呼び出し責務は現状維持

- pages/api/

  - 変更なし

- pages/
  - index.tsx: サブタイトル「OPGG風〜」の撤去、入力プレビュー位置変更に伴う構成調整

## データモデル・型定義の変更点

- 既存型 PlayerJson / PlayersJson / TeamBalancer の契約は変更しない
- UI 開閉状態やタブ状態はコンポーネントローカル state で管理する

## API変更有無と docs/team-balancer.v1.yaml への影響

- API 変更: なし
- docs/team-balancer.v1.yaml への影響: なし（更新不要）

## 既存仕様との矛盾確認と採用方針

- 10人条件との整合: 変更なし（表示のみ調整）
- 評価重み（0.3 / 0.5 / 0.2）との整合: 変更あり（総レート差の寄与を再調整）
- fromJson / playersInfo 互換性: 変更なし
- API 契約: 変更なし

補足（表示方針差分）:

- 既存仕様には「参加人数（x/10）表示へ集約」があるが、今回要望では PlayerInputForm から人数表示自体を撤去する
- 採用方針として、分割条件は分割実行ボタンの活性/非活性と理由表示で伝え、PlayerInputForm 内の人数表示は行わない
- 既存仕様には評価重み固定（0.3 / 0.5 / 0.2）があるが、今回要望では重み調整を行う
- 採用方針として、式の構造は維持しつつ重みのみ再調整し、ユニットテストと比較検証で妥当性を確認する

上記4点について仕様矛盾は確認されなかったため、追加要望を採用する。

## 実装方針

- 白背景入力は文字色黒を明示し、背景/文字コントラストを固定化する
- アコーディオンは「開いている状態」をデフォルトにし、既存の入力開始導線を維持する
- 分割画面のタブは「分割結果」を初期タブとし、履歴は必要時に切り替える
- E2E セレクタは `role=tab` / `role=button` の違いを前提に更新する
- PlayerCard の固定 light 色クラスを CSS テーマ変数クラスへ置換する（例: `bg-gray-200` → `bg-[var(--tb-surface)]`、`text-gray-600` → `text-[var(--tb-text-secondary)]`）
- Input 系ラベルは `text-slate-700` から `text-[var(--tb-text-primary)]` へ統一する
- PlayerInputForm の進捗バー（`progressWidthClassByCount` 等）を削除し、アコーディオンヘッダーの `{count}/10人` 表示も削除する
- PlayerInputForm の「10人揃いました。チーム分けを実行できます」メッセージを削除する
- 全コンポーネントで light 系固定カラークラスの棚卸しを行い、ダークテーマ変数または `dark:` プレフィックス適用クラスへ置換する
- サンプルデータ投入ボタンは `players.length === 0` のときのみ表示する
- サブタイトル「OPGG風〜」は削除し、主要操作要素の視線誘導を優先する
- 入力プレビューはレイアウト上でプレイヤー追加フォームより上に再配置する
- Copy 操作文言を「クリップボードにコピー」へ変更し、周辺文言と日本語で統一する
- 分割結果/履歴タブは共通コンテナ高（`min-h` 等）を設定し、切替時の下端ズレを防ぐ
- 分割実行中は旧結果をブラー/非表示にし、スケルトンまたは「新しいチームを計算中」表示へ切り替える
- 評価スコア重みは総レート差の寄与を下げる方向で再設定し、候補値比較を経て採用する
- 試合結果確定は確認ダイアログ（またはモーダル）を経由し、確定成功時に勝敗選択 state を初期化する

## 検証方針

- `npm run format` → `npm run format:test` → `npm run typecheck` → `npm run test` → `npm run test:e2e`
- 白背景入力での文字可読性を目視確認する
- アコーディオン開閉時に入力・送信が継続して可能か確認する
- 分割/履歴タブ切替時に表示崩れや状態欠落がないことを確認する
- PlayerCard のすべてのテキスト（名前・ランク・スコア等）がダーク背景で視認できることを目視確認する
- Input 系ラベルがダーク背景で視認できることを目視確認する
- UI 全体を通じて、ほぼ白に近い文字色または背景と同化する文字色が残っていないことを確認する
- 一括編集画面で白背景領域が支配的でないことを目視確認する
- 入力プレビューがプレイヤー追加フォームより上に表示されることを確認する
- プレイヤー追加フォーム内に人数表示（x/10）と達成メッセージが表示されないことを確認する
- プレイヤーが1人以上のときサンプルデータ投入ボタンが非表示になることを確認する
- サブタイトル「OPGG風〜」が表示されないことを確認する
- Copy 操作文言が日本語化されていることを確認する
- 分割結果/履歴タブ切替時に下端スクロール位置でレイアウトジャンプがないことを確認する
- 分割実行中に新規処理中であることがUIで明確に分かることを確認する
- 重み調整後に評価スコアの偏りが緩和され、既存テストが成立することを確認する
- 試合結果確定時に再確認が表示され、確定後に勝敗選択がクリアされることを確認する
